Test Cases and Results
1) Render multiple instances
- Create 3 instances with different ranges and theme configs.
- Expect: Each instance renders the selected date text in `tg-selected-date` and details in `tg-date-details`.
- Status: Covered by demo and smoke script (waits for formatted date).

2) Drag selection
- Action: Drag thumb/track from ~25% to ~75%.
- Expect: Date updates; progress and thumb move; hover label tracks pointer.
- Status: Automated in `scripts/screenshot.js` (boundingBox + mouse drag).

3) Long-press acceleration (fine-tune buttons)
- Action: Hold `<` or `>` and observe step escalation: 1 day → 3 days (>600ms) → week (>1.5s) → month (>3s).
- Expect: Speed indicator text and visual speed classes update; date changes clamped to range.
- Status: Manual validation recommended; automated timing-sensitive checks are not added yet.

4) Keyboard controls
- Action: ArrowLeft/Right = ±1 day, ArrowUp/Down = ±7 days, `T` = today.
- Expect: Date updates; today match toggles `is-today` style.
- Status: Manual validation recommended (demo page instructions).

5) Today marker
- Action: Click Today label below the red marker.
- Expect: Selected date jumps to today.
- Status: Manual validation recommended.

6) Year marks and labels
- Expect: 5-year marks; decade and major marks with labels at 20/50-year milestones; correct position across range.
- Status: Visual inspection; generated in `#generateYearMarks()`.

7) Theming
- Options: `theme: 'dark' | 'light' | 'auto'` + optional palette overrides or CSS vars.
- Expect: Colors reflect theme; `auto` follows `prefers-color-scheme` in supported browsers.
- Status: Toolbar toggles in demo; CI captures light and dark component screenshots.

8) API
- get/set: `getDate()`, `setDate(date)`, `destroy()`; DOM `change` event fires on updates.
- Expect: `setDate` respects range; event detail includes a Date; destroy removes UI.
- Status: Manual console verification recommended; release consumers can rely on UMD/ESM builds.

9) Shadow DOM
- Config: `shadow: true|false`.
- Expect: With shadow true, styles encapsulated; with false, page CSS vars can style component directly.
- Status: Demo 3 uses Shadow DOM true; manual sanity check recommended for both modes.

10) Range boundaries
- Config: `startDate|startYear`, `endDate|endYear`.
- Expect: Clamped selection; out-of-range `setDate` is ignored.
- Status: Manual validation recommended with extreme dates.

11) Accessibility
- Expect: Group role wrapper, slider `role=slider` with `aria-valuemin|max|now|text`, `aria-live` on selected date, tab focus on thumb.
- Status: Verified in DOM; manual screen-reader pass recommended.

12) Performance
- Expect: rAF-driven updates; smooth drag; no blocking dependencies.
- Status: Observed; not benchmarked in CI.

Known Issues / Notes
- Timing-based long-press tests are best validated manually; CI does not simulate press durations.
- Cross-browser testing is limited in CI to Chromium; manual checks recommended in Safari/Firefox.
- `auto` theme depends on `prefers-color-scheme` support.

Recommendations
- Add targeted E2E tests for long-press acceleration (use controlled timers / reduced thresholds in a test build).
- Add mobile touch-specific tests (touchstart/move) in Playwright.
- Add a11y audit (axe-core) for index.html.
